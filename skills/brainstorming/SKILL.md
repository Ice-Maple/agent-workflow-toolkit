# 头脑风暴：从想法到需求文档

通过自然的对话式提问，帮用户把模糊的想法梳理成清晰的需求，最终落盘到本地文件。轻量、专注，只做头脑风暴这一件事。

## 何时使用

当用户提出一个想法、需求、功能、或设计方向，且希望先把它想清楚、记下来时使用本 skill。例如：

- "我想给游戏加一个 XX 系统的玩法，帮我梳理一下需求"
- "帮我想想这个功能怎么做"
- "头脑风暴一下 / 梳理一下需求"

## 核心原则

1. **一次只问一个问题**——不要用多个问题淹没用户。需要深入的话题拆成多轮。
2. **优先用选择题**——给 A/B/C 选项比开放题更容易回答，开放题也可以。
3. **先把目的问清楚**——为什么要做？谁用？解决什么问题？再看怎么做。
4. **克制，不要过度设计**——YAGNI，砍掉不必要的功能，聚焦核心。
5. **先探索再提问**——提问前先看一眼项目现状（相关文件、文档、代码）。

## 可视化伴侣（按需）

遇到**看图比读文字更清楚**的问题（原型、布局、架构图、视觉对比）时，可以提供浏览器可视化伴侣：

- **按需、不要一上来就提**。第一次出现真正适合可视化的问题时，单独用一条消息提议（只说提议，不带其他问题）。同意才用；拒绝就纯文字，不再重复提。
- **逐问题决定**：即使同意了，也要逐个问题判断——视觉题用浏览器，文字/概念题用终端。
- 同意后，**先读本目录的 `visual-companion.md`** 了解如何创建和展示 HTML 原型（自包含 HTML 写到 `docs/brainstorms/.visual/`，用默认浏览器打开）。

## 流程

### 1. 探索项目上下文
快速看一眼当前项目状态：相关文件、已有文档、最近改动。提问要结合项目实际，而不是泛泛而谈。

### 2. 逐个澄清问题
一次一个问题，按这个顺序逐步明确：

- **目的与动机**：为什么要做这个？解决什么痛点？
- **范围与边界**：包含什么、不包含什么？这次做到哪一步？
- **成功标准**：做成什么样算成功？有没有可衡量的目标？
- **约束条件**：技术限制、时间限制、必须兼容的东西？

每问完一个，根据回答决定是否需要追问。如果用户回答已经清楚了，就进入下一步。

### 3. 提出 2-3 个方案
针对核心问题，给出 2-3 个不同思路，每个说明：

- 大致做法
- 优点 / 代价
- 你的推荐 + 推荐理由

把推荐方案放第一个，说清楚为什么推荐。

### 4. 呈现需求概要
把对话得到的信息整理成清晰的需求概要，分小节呈现，每节按复杂度决定篇幅（简单的几句话，复杂的可以更长）。覆盖：

- 背景与目标
- 核心需求（功能 / 非功能）
- 约束
- 待定的开放问题
- 下一步

呈现后确认用户是否认可。有异议就回去澄清，不要跳过确认直接落盘。

### 5. 落盘保存
用户确认后，把需求文档写到 `docs/brainstorms/YYYY-MM-DD-<topic>.md`：

- **路径**：相对项目根目录的 `docs/brainstorms/`
- **文件夹不存在就创建**
- **文件名**：`YYYY-MM-DD-<topic>.md`
  - 日期取当天（例：`2026-07-15`）
  - `<topic>` 是从主题提炼的 kebab-case 短标识，全小写、用连字符分隔，中文主题可转成简短拼音或英文 slug（例：玩家离线收益 → `offline-reward`）
  - 完整示例：`docs/brainstorms/2026-07-15-offline-reward.md`
- **不自动 git 提交**——只写文件，除非用户明确要求提交。

### 6. 收尾
告诉用户文件保存在哪里，列出待定的开放问题供后续决定。到此结束，不要自动跳转到实现/写代码。

## 文档模板

落盘时使用以下结构（按需增删，保持简洁）：

```markdown
# <主题标题>

- 日期：YYYY-MM-DD
- 状态：草案 / 已确认

## 背景与目标
<为什么要做，想达到什么效果>

## 核心需求
### 功能需求
- ...
### 非功能需求
- ...

## 约束
- ...

## 方案
<选定的方向，以及考虑过的备选>

## 开放问题
- [ ] ...

## 下一步
- ...
```

## 常见误区

- **一次问太多**：违反"一次一问"，让用户疲劳。拆成多轮。
- **不探索就提问**：明明项目里有相关代码/文档却没看，问出已知答案的问题。
- **过度设计**：把简单需求膨胀成大系统。砍掉非必要部分。
- **没确认就落盘**：跳过用户确认直接写文件，写完才发现方向错了。
- **自动开始写代码**：本 skill 只负责头脑风暴和记录，实现是后续单独的事。
