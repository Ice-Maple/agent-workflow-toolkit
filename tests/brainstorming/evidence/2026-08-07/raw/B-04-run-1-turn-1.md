| 方案 | 核心做法 | 主要收益 | 主要代价 | 适用条件 |
|---|---|---|---|---|
| JSONL | 每行保存一条任务记录 | 可直接阅读；Git diff 清晰；实现简单；500 条以内足够 | 复杂查询、事务和并发能力较弱；更新旧记录可能产生较大 diff | 数据量小、单用户、以查看和版本追踪为主 |
| SQLite | 使用单文件关系数据库 | 事务可靠；结构化约束和查询能力强；后续扩展空间大 | 文件是二进制，无法直接阅读，普通 Git diff 几乎没有价值 | 查询、关联、并发或一致性比版本差异更重要 |

当前判断：选择 JSONL。

决定性标准是“能直接查看和 Git diff”，而 SQLite 在这一点上存在结构性劣势。低频、单用户、不超过 500 条且不重视复杂查询，也意味着 SQLite 的主要优势暂时无法抵消该劣势。这个判断成立的前提是任务记录不需要频繁原地更新，也不要求跨多条记录的事务一致性。

你倾向采用 JSONL，还是希望因未来可能增加复杂查询而选择 SQLite？
