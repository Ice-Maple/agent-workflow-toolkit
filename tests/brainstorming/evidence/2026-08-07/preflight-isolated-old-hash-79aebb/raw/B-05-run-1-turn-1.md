已确认的设计边界：

- 接入 3 个外部 CLI adapter。
- 任务意图、执行尝试、完成判断分别记录。
- 支持超时、取消和 resume。
- 第一版不使用数据库、daemon 或完整 mailbox。
- 因此需要轻量本地持久化，但具体格式、原子性和恢复规则仍待设计。

先确认最影响接口与恢复语义的一点：第一版的主要使用者是谁？

1. **本地交互用户**：人在终端启动、观察、取消和恢复任务。
2. **自动化调用方**：脚本或 CI 调用，重点是稳定退出码、结构化输出和无人值守恢复。
3. **两者同等重要**：从第一版起保证交互与自动化行为一致，但接口和状态语义会更复杂。

请选择主要方向，也可以说明两者的优先级。
