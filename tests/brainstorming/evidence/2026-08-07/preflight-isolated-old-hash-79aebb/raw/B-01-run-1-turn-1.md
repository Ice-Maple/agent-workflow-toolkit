# CLI `request_timeout` 配置设计

## 背景与目标

允许用户在现有 `settings.yaml` 中配置请求超时时间，同时保持旧配置行为不变。

## 核心需求

在 `settings.yaml` 增加可选字段：

```yaml
request_timeout: 60
```

字段语义：

- 单位：秒。
- 字段缺失：使用默认值 `30`，与当前行为一致。
- 字段存在：只接受正整数。
- `0`、负数、小数、字符串、布尔值和 `null` 均视为无效。
- 无效配置通过现有校验入口报告配置错误，不进入请求执行阶段。

## 处理流程

1. 继续使用现有 YAML 解析入口读取 `settings.yaml`。
2. 在现有配置校验中加入 `request_timeout` 的类型和值域检查。
3. 配置归一化时，将缺失字段补为 `30`。
4. 发起请求时使用归一化后的超时值，替代当前固定的 30 秒。

## 约束与范围

- 不增加依赖。
- 不增加配置文件、环境变量、命令行参数或其他存储机制。
- 不另建解析、校验或默认值处理入口。
- 不改变除请求超时之外的行为。
- 不设置额外上限；任何正整数都符合配置规则。

## 验收要点

- 旧版 `settings.yaml` 不包含该字段时，超时仍为 30 秒。
- `request_timeout: 60` 时，请求超时为 60 秒。
- 所有非正整数值均由现有配置校验机制拒绝。
- 配置错误沿用现有错误呈现和退出方式。
- 现有配置项的解析与行为不受影响。
